relabel_configs

抓取前 (Before Scrape) 的目标管理器

核心作用

管理通讯录。在发请求去抓数据之前，用来筛选要抓取的机器 (Target)，或者修改抓取目标的地址和附加在目标上的默认标签。

常见使用场景

  • 1. 丢弃不需要的目标 (Drop/Keep) 比如服务发现找到了 100 个 Pod，但只抓取带有 env=prod 标签的 Pod，直接忽略测试环境，避免产生无效 HTTP 请求。
  • 2. 修改抓取地址 (__address__) 默认目标 IP 是局域网 IP，但在跨集群监控时，可能需要将抓取地址替换为外网暴露的域名或通过代理端口来抓取。
  • 3. 提取和重命名元数据标签 K8s 自动生成的标签太长（如 __meta_kubernetes_pod_name），提取它的值并重命名为短标签 pod 附加到目标上。

metric_relabel_configs

抓取后 (After Scrape) 的指标清洗器

核心作用

精简日记本。数据已经抓回来了，但在存入本地硬盘 (TSDB) 之前，把没用的、太耗空间的指标删掉，或者把指标的名字/标签改掉。

常见使用场景

  • 1. 丢弃高基数/无用指标（省钱/省内存利器） 某个组件暴露了成百上千个你根本不看的调试指标（比如 cAdvisor 的某些网络详细指标），或者某个标签包含用户 ID（基数极高易致 OOM），直接 Drop 掉。
  • 2. 删除敏感/冗余标签 目标暴露的指标里带有了敏感的 token 标签，或者带有和你的元数据标签重复的标签（冲突时）。通过 labeldrop 把特定标签删掉。
  • 3. 标准化指标标签值 例如有的开发同事把 HTTP 状态码写成了 status="200 OK"，有的写成 status="200"。你可以在这里用正则统一清洗替换为数字，方便 Grafana 统一画图。
