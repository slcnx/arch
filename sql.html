SQL 智能诊断算法原理

图解监控平台是如何通过 归一化 和 TF-IDF聚类 从海量日志中揪出你的慢查询的。

核心动作：去除变量，保留骨架

线上每秒可能产生成百上千条长得差不多的 SQL，唯一的区别只是查询的 question_id 不同。归一化就是把具体的数值替换为 ?，并统一大小写和空格。

原始 SQL 日志 (海量)
select question_id, user_answer, count(*) as count from `yjy_user_answer_log` where `question_id` in ('377488') group by question_id, user_answer
SELECT question_id, user_answer, count(*) as count FROM yjy_user_answer_log WHERE question_id IN ('999123', '999124') GROUP BY question_id, user_answer
select question_id,user_answer,count(*) as count from `yjy_user_answer_log` where `question_id` in ('1024') group by question_id,user_answer
↓ 归一化处理 ↓
归一化后的 SQL 模板 (唯一)
select question_id, user_answer, count(*) as count
from yjy_user_answer_log
where question_id in (?)
group by question_id, user_answer

核心动作：词频-逆文档频率 (提取特征)

AI 无法直接理解 SQL，需要把它拆成词。TF(词频)：这个词在这句SQL里出现得多不多？ IDF(逆文档频率)：这个词在所有SQL里是不是很罕见？ 像 SELECT 到处都有，权重极低；而你的表名和字段名很特别，权重极高。

select question_id, user_answer, count(*) as count from yjy_user_answer_log where question_id in (?) group by question_id, user_answer

核心动作：K-Means 聚类 (物以类聚)

有了上一步的权重向量，AI 把几万种 SQL 模板扔进高维空间。特征相似的 SQL 会在空间中靠在一起，形成一个“簇(Cluster)”。 这样，DBA 只要优化这一个“簇”，就能解决线上 30% 的性能问题。

Cluster A (你的 SQL)

特征标签: question_id, user_answer, group by
select ... group by question_id, user_answer
占总慢查询: 45% (高频!)

Cluster B

特征标签: app_id, subject_id, part_id
select count(*) ... where app_id = ? ... group by part_id
占总慢查询: 20%

Cluster C

特征标签: insert, values
insert into yjy_user_answer_log ...
占总慢查询: 5%
💡 结论：因为你的 SQL 被聚类识别为 Cluster A (占比45%) 的典型代表，所以你针对它建立 Projection 1，是一次收益极高的优化！
